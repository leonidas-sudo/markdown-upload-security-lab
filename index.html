Markdown Upload Security Lab

A static, browser-only practice site for authorized file-upload and Markdown-rendering checks.

1. Select a file

The demo accepts a .md, .markdown, or .pdf filename for validation practice. No file is sent to a server.

Choose a file to begin.

Client-side checks are not a substitute for server-side validation. GitHub Pages cannot demonstrate backend upload handling or SSRF.

2. Markdown preview

Safe preview escapes raw HTML. Isolated HTML preview uses a sandboxed iframe without same-origin access to this page.

Preview will appear here.

The isolated mode is for observing rendering behavior only. It is not a full browser-security test and should not be used as a production renderer.

3. Test ideas

  • Extension and MIME: compare filename extension, browser-reported MIME type, and content. Try a renamed file and a double extension.
  • HTML rendering: use the provided sample to see how raw HTML is treated. In a real target, confirm whether any script executes in the target application's origin.
  • Remote resources: add a link or image to a domain you control and inspect access logs. A browser request is not proof of SSRF; SSRF requires a backend-originated request.
  • Authorization: in the target application, replay document read/update/delete requests with a different workspace's account and IDs.
  • Resource limits: test file size and malformed inputs only in an authorized, controlled environment.
Scope limitation: This is a static GitHub Pages lab. It does not store uploads, call a backend, parse PDFs, access internal IPs, or make server-side URL requests.
